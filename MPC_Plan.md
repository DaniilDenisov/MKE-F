# План расширения ограничений, MPC и концевых освобождений

> Реализованы этапы A–C: маски SPC, типы 5–7, общий справочник, однородные MPC, все три решателя, редактор, помощник оси и результаты v3. Этапы D–E (концевые освобождения и полное исследование NAFEMS) отложены. Раздел 2 описывает исходное состояние до реализации.
>
> Окончательные решения: только rhs=0; зависимая СС не может быть SPC; коэффициенты помощника не пересчитываются после изменения геометрии. Невязка reactions сохранена для совместимости, опорные реакции и силы MPC экспортируются отдельно. Проверки: tests/test_support_masks.m, tests/test_mpc.m, scripts/test_mpc_browser.cjs и backend/tests/test_octave_runner.py.

## 1. Назначение документа

Этот документ описывает отдельное направление развития МКЭ-Ф: более точное
задание узловых ограничений, линейные многоточечные связи (MPC) и концевые
освобождения рамных элементов.

Главная практическая цель — устранить ограничения текущей модели опор и дать
возможность корректно собирать шарнирные и кинематически связанные системы.
Задача NAFEMS Challenge Problem 5 является одним из проверочных примеров, но
реализация должна быть общей, а не зашитой под одну геометрию.

Изменение формулировки матриц массы в эту работу не входит. МКЭ-Ф продолжает
использовать существующие согласованные матрицы массы.

## 2. Проверенное текущее состояние

### 2.1. Узловые ограничения

Сейчас секция `bcfix` содержит записи вида:

```text
type,node,0,0,0
```

Функция `src/analysis/common/partitionDOFs.m` поддерживает четыре типа:

| Тип | Ферма 112 | Рама 113 |
|---:|---|---|
| 1 | закреплены `ux`, `uy` | закреплены `ux`, `uy`, `thetaZ` |
| 2 | закреплена `uy` | закреплены `uy`, `thetaZ` |
| 3 | закреплена `ux` | закреплены `ux`, `thetaZ` |
| 4 | закреплены `ux`, `uy` | закреплены `ux`, `uy`, поворот свободен |

Для двухстепенного ферменного узла представлены все полезные ненулевые
комбинации. Для рамного узла отсутствуют три комбинации:

- закрепить только `ux`, оставив свободными `uy` и `thetaZ`;
- закрепить только `uy`, оставив свободными `ux` и `thetaZ`;
- закрепить только `thetaZ`, оставив свободными `ux` и `uy`.

Из-за этого текущие варианты «свободно только `ux`» и «свободно только `uy`»
не являются обычными катковыми опорами рамной модели: они дополнительно
запрещают поворот.

### 2.2. Ограничения решателя

Текущий механизм только исключает отдельные глобальные СС из системы. Он не
умеет задавать соотношение между несколькими перемещениями, например:

```text
uy(3) = 0.5*uy(1) + 0.5*uy(2)
```

Также в модели нет освобождений на концах отдельных элементов. Общий рамный
узел всегда означает общие `ux`, `uy` и `thetaZ` для всех присоединённых
элементов и поэтому передаёт изгибающий момент.

## 3. Целевая модель обычных узловых ограничений

### 3.1. Представление внутри программы

Внутренне опору следует хранить не как неочевидный номер типа, а как явную
маску закреплённых СС:

```text
node
fixUx
fixUy
fixThetaZ
```

Номер типа остаётся частью текстового формата для обратной совместимости, но
парсер сразу преобразует его в маску. Решатель должен работать с маской, а не
с ветвлением по номерам 1–7.

### 3.2. Полный набор типов для рамы

Старые типы 1–4 сохраняют прежний смысл. Добавляются типы 5–7:

| Тип | Закреплённые СС | Рекомендуемая подпись в интерфейсе |
|---:|---|---|
| 1 | `ux`, `uy`, `thetaZ` | Fixed: ux, uy, thetaZ |
| 2 | `uy`, `thetaZ` | Fixed: uy, thetaZ |
| 3 | `ux`, `thetaZ` | Fixed: ux, thetaZ |
| 4 | `ux`, `uy` | Pinned support: ux, uy |
| 5 | `ux` | Roller X: ux |
| 6 | `uy` | Roller Y: uy |
| 7 | `thetaZ` | Rotation restraint: thetaZ |

В выпадающем списке нужно показывать не только бытовое название опоры, но и
точный набор закрепляемых СС. Это устраняет неоднозначность направлений
«горизонтальная/вертикальная опора».

Для фермы в списке показываются только три уникальные комбинации:

- `ux, uy`;
- только `ux`;
- только `uy`.

Старый тип 4 для фермы по-прежнему читается как полное закрепление, но новые
файлы должны сериализоваться в единственной канонической форме.

### 3.3. Изменения интерфейса

- Обновить список в `preprocessor/js/app.js`.
- Перенести подписи и маски в общий справочник вместо дублирования логики.
- Расширить `shared/support-markers.js` обозначениями опор, у которых свободен
  поворот и закреплена только одна поступательная СС.
- В таблице Supports показывать отдельную краткую колонку `Fixed DOFs`.
- При смене семейства элементов повторно проверять допустимость типа опоры.
- Обновить SVG-легенду и справочник, чтобы направление ролика совпадало с
  запрещённым перемещением.

### 3.4. Совместимость и диагностика

- Старые файлы с типами 1–4 должны читаться без изменения результатов.
- Тип 7 должен отклоняться для фермы 112: в узле отсутствует `thetaZ`.
- Повторное закрепление одной и той же СС остаётся ошибкой.
- Сообщение об ошибке должно называть узел и конкретную СС, а не только номер
  типа опоры.
- Ненулевые заданные перемещения пока остаются вне объёма этой работы.

## 4. Линейные многоточечные связи MPC

### 4.1. Назначение

MPC задаёт линейное соотношение между несколькими глобальными СС:

```text
a1*u1 + a2*u2 + ... + an*un = b
```

Первая версия должна поддерживать однозначную форму «зависимая СС через
ведущие СС»:

```text
uDependent = b + c1*uMaster1 + ... + cn*uMasterN
```

Для модального и переходного анализа на первом этапе допускаются только
однородные связи `b = 0`. Ненулевую правую часть можно оставить для отдельного
этапа статических заданных перемещений.

### 4.2. Реализованный текстовый формат

Повторяемая секция после элементов:

```text
mpc
1
3,2,0,2,1,2,0.5,2,2,0.5
```

Запись: `depNode,depDOF,rhs,masterCount,node,dof,coefficient,...`.
Зависимая СС указана явно, её коэффициент в уравнении равен +1.
Пример задаёт `uy(3)=0.5*uy(1)+0.5*uy(2)`. Коды: 1=ux, 2=uy,
3=thetaZ; ненулевой rhs отклоняется во всех анализах. Номера уравнений
соответствуют порядку записи во всех секциях. Формат результатов и знаки сил
описаны в `postprocessor/schema-v3.md`.

### 4.3. Специализированный помощник «узел на оси элемента»

Для Challenge Problem 5 нужен удобный генератор связи, удерживающей
промежуточный узел `k` на линии между концами члена `i` и `j`.

Пользователь выбирает:

- начальный узел `i`;
- конечный узел `j`;
- промежуточный узел `k`.

Препроцессор вычисляет положение `xi` узла вдоль члена и создаёт линейное
уравнение для поперечного перемещения в локальной системе. После раскрытия
локальных компонент уравнение связывает глобальные `ux` и `uy` трёх узлов.

Это должен быть только генератор обычного MPC. Решатель не должен содержать
специальной ветви для NAFEMS или для «узла на стержне».

### 4.4. Преобразование системы

Рекомендуемый алгоритм первой версии — точное исключение зависимых СС:

```text
u = T*q + u0
```

Для однородных связей `u0 = 0`. Редуцированные матрицы и нагрузки:

```text
Kr = T'*K*T
Mr = T'*M*T
Fr = T'*(F - K*u0)
```

После решения восстанавливается полный вектор:

```text
u = T*q + u0
```

Матрицу `T` следует строить разреженной. Это сохраняет симметрию системы и не
добавляет искусственную штрафную жёсткость. Штрафной метод как основной
механизм использовать не следует: он зависит от произвольного коэффициента и
может искажать собственные частоты.

### 4.5. Совместная работа SPC и MPC

Обычные опоры и MPC должны объединяться до решения. Необходимы проверки:

- зависимая СС не может одновременно быть закреплена SPC; такой конфликт отклоняется;
- одна СС не может быть зависимой в двух уравнениях;
- граф зависимостей не должен содержать циклов;
- ссылка на несуществующий узел или СС является ошибкой входа;
- уравнение с нулевыми коэффициентами является ошибкой;
- несовместные и линейно зависимые ограничения должны диагностироваться до
  факторизации `K`;
- после преобразования должны отсутствовать неучтённые механизмы.

### 4.6. Реакции связей

После восстановления полного `u` вычисляется исходный невязочный вектор:

```text
r = K*u - F
```

Для обычных опор соответствующие компоненты являются реакциями. Для MPC нужно
отдельно восстанавливать обобщённые силы связей и выдавать их в результатах с
номером уравнения и знаком, определённым документацией. Нельзя смешивать силы
MPC с опорными реакциями без явной маркировки.

## 5. Концевые освобождения рамных элементов

### 5.1. Физический смысл

Концевое освобождение относится к конкретному концу конкретного элемента.
Освобождение `Mz` означает, что конец не передаёт изгибающий момент, хотя его
поступательные перемещения остаются связанными с узлом.

Это не то же самое, что опора типа 4:

- опора типа 4 закрепляет `ux` и `uy` узла относительно основания;
- освобождение `Mz` не закрепляет узел и только разрывает передачу момента
  между элементом и узловым поворотом.

### 5.2. Формат данных

Для обратной совместимости лучше не менять число полей записи элемента 113.
Предлагается отдельная секция:

```text
releases
2
1,1,Mz
2,2,Mz
```

Поля: `elementId,end,component`, где `end` равен 1 или 2. В первой версии
поддерживается только компонент `Mz`. Формат должен позволять позднее добавить
`N` и `V`, не меняя старые записи.

Если числовой парсер должен оставаться полностью числовым, `Mz` можно заменить
кодом компоненты, но в интерфейсе и диагностике всё равно следует показывать
физическое имя.

### 5.3. Рекомендуемая реализация

Для динамических задач нельзя просто занулить строку и столбец жёсткости:
получится паразитная СС с массой и нулевой жёсткостью. Также нежелательно
безоговорочно применять только статическую конденсацию, потому что она может
исказить динамику освобождённого конца.

Предпочтительный вариант — release-aware карта СС:

- `ux` и `uy` конца элемента используют обычные глобальные СС узла;
- неосвобождённый `thetaZ` использует общий узловой поворот;
- освобождённый `thetaZ` получает внутреннюю, принадлежащую этому концу
  элемента вращательную СС;
- исходные локальные `K` и `M` рамного элемента собираются без искусственного
  зануления коэффициентов;
- неиспользуемые глобальные узловые повороты не должны оставаться в системе.

Так разные элементы в одном геометрическом узле имеют общие перемещения, но
могут вращаться независимо. Подход сохраняет согласованную массу и подходит
для модального анализа NAFEMS.

Это изменение затрагивает предположение `dofPerNode = 3` и требует отделить
геометрический узел от полного реестра глобальных СС. До реализации следует
спроектировать общий DOF registry, поддерживающий узловые и внутренние СС.

### 5.4. Интерфейс и результаты

- В таблице Elements для типа 113 добавить `Release at end 1` и
  `Release at end 2`.
- На схеме показывать маленький кружок у освобождённого конца, а не в центре
  геометрического узла.
- В карточке элемента явно писать `Mz1 released` или `Mz2 released`.
- В `localEndForces` момент на освобождённом конце должен быть нулём с учётом
  численного допуска.
- Узловой момент `Mz` нельзя прикладывать к узловому повороту, который не
  связан ни с одним неосвобождённым концом. Такая нагрузка должна вызывать
  понятную ошибку модели.

## 7. Обязательные тесты приёмки

### Обычные опоры

- Все семь комбинаций рамных ограничений дают ожидаемые `fixedDOFs`.
- Для фермы доступны только три уникальные комбинации.
- Старые case-файлы дают побитно тот же набор свободных СС.
- GUI, парсер Octave и браузерный валидатор используют одну таблицу семантики.

### MPC

- Связанный узел точно выполняет заданное уравнение.
- Жёсткий перенос и поворот члена не создают ложных деформаций.
- Цикл и конфликт MPC/SPC выявляются до решения.
- Матрицы после преобразования остаются симметричными.
- Статическое равновесие выполняется с учётом сил связей.
- Модальная задача не получает ложных нулевых форм из промежуточных узлов.

### Освобождения

- Статический момент на освобождённом конце равен нулю.
- Поступательные перемещения соединённых концов совпадают.
- Два присоединённых элемента могут иметь разные концевые повороты.
- Неосвобождённая модель полностью совпадает с текущими результатами.
- В модальном расчёте не возникает искусственной нулевой вращательной формы.

## 9. Критерий завершения

Работа считается завершённой, когда пользователь может:

1. независимо закрепить любую одну или любую комбинацию СС рамного узла;
2. задать и увидеть линейную связь между СС нескольких узлов;
3. корректно измельчить ферменный член без паразитных поперечных механизмов;
4. освободить `Mz` на выбранном конце рамного элемента;
5. выполнить статический, модальный и переходный расчёт без искусственных
   нулевых СС;
6. получить реакции опор, силы MPC и нулевой момент на освобождённом конце;
7. воспроизвести соответствующие части NAFEMS Challenge Problem 5 без
   специальных поправок в решателе.
