# Равномерные нагрузки на рамные элементы: согласованная реализация

## Объём

Статические равномерные qx/qy в локальной и глобальной системах для рам 113,
совместно с узловыми Fx/Fy/Mz. Полный путь: case-файл → редактор → решение →
реакции и усилия → JSON → эпюры и отображение нагрузок.

Линейные и внутренние сосредоточенные нагрузки, элементные нагрузки на 112,
собственный вес, временные амплитуды и сочетания в эту версию не входят.

## Входные данные и численное ядро

```text
eload_uniform
1
20,elementId,coordinateSystem,qx,qy
```

Система 1 — local, 2 — global XY. Интенсивности заданы на единицу фактической
длины элемента. Локальная x направлена от первого узла ко второму, y — на +90°.
Секции и записи на один элемент суммируются. Нулевые обе компоненты, неконечные
значения, неверные ссылки, типы и неподдерживаемые виды анализа отклоняются.

Исходные записи хранятся отдельно в elementLoads. Узловые нагрузки сохраняют
существующие allForceBCs/forceBoundaryConditions и loads в препроцессоре.
Отсутствие elementLoads в старой модели означает отсутствие элементных нагрузок.

buildStaticLoad складывает buildNodalLoadVector и buildElementLoadVector.
Локальный согласованный вектор для длины L:

```text
[qx*L/2; qy*L/2; qy*L^2/12; qx*L/2; qy*L/2; -qy*L^2/12]
```

Глобальная сборка использует T' * feLocal. Концевые усилия восстанавливаются
как Klocal*ulocal-feLocal; реакции — как K*u-F. Равновесие дополнительно
вычисляется по исходным результирующим распределений и их моментам.
Прямые вызовы modal/transient также запрещают элементные нагрузки.

## Редактор: принятые решения

- Отдельная таблица Element loads и создание на выбранном элементе 113 в статике.
  Начальная нагрузка: Global, qx=0, qy=-1.
- Local ↔ Global пересчитывает компоненты без изменения физической нагрузки.
  При некорректной геометрии переключение отклоняется.
- Любая фактическая правка концов, A, E, rho или I удаляет все распределённые
  нагрузки изменённого элемента. Повторный ввод прежнего значения — без удаления.
- Изменение координат узла удаляет распределённые нагрузки его элементов,
  сохраняя узловые нагрузки и закрепления.
- Удаление элемента удаляет его распределённые нагрузки; его узлы сохраняются.
- Удаление узла каскадно удаляет примыкающие элементы и их распределённые
  нагрузки, а также закрепления и нагрузки самого удалённого узла.
- Соседние изолированные узлы не удаляются. Номера оставшихся ссылок обновляются
  без переноса нагрузок на другие объекты и без удаления незатронутых нагрузок.
- Одна операция Undo/Redo восстанавливает/повторяет весь каскад. Сообщение после
  действия сообщает количество удалённых объектов; подтверждение не требуется.
- Удалённый узел наблюдения transient сбрасывается; требуется новый выбор.
- Смена вида анализа сохраняет нагрузки, но несовместимость блокирует запуск
  и экспорт. Текстовый импорт валидирует записи, не удаляя их автоматически.

## Результаты

JSON v2 используется только для моделей с элементными нагрузками; остальные
результаты сохраняют v1. Новый просмотрщик читает обе версии. API принимает обе.
В v2 экспортируются исходные nodalLoads, elementLoads и equivalentLocalLoadVector
для каждого элемента. Векторы и коллекции остаются массивами при любом размере.

Постпроцессор показывает реальные узловые нагрузки и распределения отдельно,
не рисует дополнительные эквивалентные узловые силы. Стрелки видны на исходной
и деформированной схемах; их направление определяется исходной геометрией.

```text
N(x) = -f1 - qx*x
V(x) = -f2 - qy*x
M(x) = -f3 + f2*x + qy*x^2/2
```

Эпюры учитывают внутренний экстремум момента. Скалярные axialStrain,
axialStress, axialForce — средние осевые значения; StressCalc также возвращает
среднее осевое напряжение рам. Аналитическое восстановление внутреннего прогиба
не добавляется: отображение сохраняет интерполяцию перемещений конечного элемента.

## Проверки и примеры

- tests/test_element_loads.m: консоль, простые опоры, два защемления, чистый Mz,
  осевая нагрузка, наклонный элемент, суперпозиция и погашение, виртуальная работа,
  равновесие, ошибочный ввод, legacy и JSON v2.
- Браузерные наборы: импорт/экспорт, Local/Global, каскады и перенумерация,
  переменное N/V/M, внутренний максимум, отсутствие двойных нагрузок, SVG/PNG.
- scripts/test_browser.cjs: настоящий интерфейс, оба редактора координат,
  Undo/Redo, удаление узла, смена анализа и загрузка результата GNU Octave.
- backend/tests/test_octave_runner.py: новый пример через API и настоящий Octave.
- examples/cases/CaseUniformFrame.txt: L=2 м, qY=-1000 Н/м, E=200 ГПа,
  I=1e-5 м^4. Реакции Fy=2000 Н, Mz=2000 Н·м; v(L)=-0.001 м.

Численные и API-тесты выполняются в Docker; публикация релиза не входит в работу.
Контракт результатов описан в postprocessor/schema-v2.md, пользовательские
правила — в reference/10-input-format.html.
