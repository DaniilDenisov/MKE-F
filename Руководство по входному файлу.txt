РУКОВОДСТВО ПО ВХОДНОМУ ФАЙЛУ МКЭ-Ф

1. Область применения

Программа решает линейные задачи малых перемещений в глобальной плоскости X-Y:

- плоские фермы из стержней типа 112;
- плоские рамы Эйлера–Бернулли из элементов типа 113;
- статический, модальный и переходный расчёты без демпфирования.

Смешивать элементы 112 и 113 в одном файле нельзя. Такой файл отклоняется с
явным сообщением, потому что ферменные и рамные узлы имеют разное число степеней
свободы. Распределённые нагрузки, ненулевые заданные перемещения, пластичность,
геометрическая нелинейность и деформация сдвига рамного элемента не реализованы.

2. Единицы

Программа не преобразует единицы. Все данные должны образовывать согласованную
систему. Рекомендуемая система СИ:

- координаты X,Y,Z и перемещения: м;
- площадь A: м^2;
- модуль Юнга E и напряжения: Па;
- плотность rho: кг/м^3;
- момент инерции I: м^4;
- силы Fx,Fy: Н;
- момент Mz: Н*м;
- время: с;
- частота: Гц.

Координата Z читается для совместимости формата, но расчёт остаётся двумерным.
Силы Fz и перемещения uz отсутствуют.

3. Общие правила синтаксиса

Файл читается до конца. Ограничения на число секций нет. Пустые строки и строки,
начинающиеся с символа #, пропускаются. После маркера секции указывается целое
число записей, затем ровно это число строк данных.

Рекомендуемый порядок:

1) nodes;
2) elems_112 или elems_113;
3) bcfix;
4) секции нагрузок.

Секция nodes должна предшествовать элементам, а элементы — опорам и нагрузкам.
Повторные секции элементов одного типа, bcfix и нагрузок добавляют записи к уже
прочитанным. Повторная секция nodes запрещена. Ошибка содержит имя файла, номер
строки и описание неверной записи.

4. Узлы

Формат:

nodes
<количество узлов>
X,Y,Z
...

Номера узлов назначаются порядком строк: первая строка координат — узел 1,
вторая — узел 2 и т.д. Координаты должны быть конечными числами.

5. Элементы

Плоский стержень фермы:

elems_112
<количество элементов>
112,node1,node2,A,E,rho

Узловые степени свободы: [ux,uy]. Элемент воспринимает только осевую силу.

Плоский элемент рамы:

elems_113
<количество элементов>
113,node1,node2,A,E,rho,I

Узловые степени свободы: [ux,uy,thetaZ]. Используется теория
Эйлера–Бернулли. Матрица масс согласованная.

node1 и node2 должны быть различными целыми номерами существующих узлов. A, E,
rho и I должны быть положительными конечными числами. Число полей проверяется
строго.

6. Опоры

Формат:

bcfix
<количество записей>
type,node,0,0,0

Поддерживаемые типы:

type=1: закрепить все степени свободы узла.
type=2: оставить свободной ux; остальные степени закрепить.
type=3: оставить свободной uy; остальные степени закрепить.
type=4: закрепить ux и uy; у рамного узла оставить свободной thetaZ.

Для ферменного узла type=4 совпадает с полным закреплением. Последние три поля
зарезервированы и должны быть равны нулю: ненулевые заданные перемещения пока не
поддерживаются. Повторное закрепление одной степени свободы выявляется перед
решением.

7. Узловые нагрузки

Для фермы компоненты нагрузки [Fx,Fy], для рамы [Fx,Fy,Mz]. Поле Mz в строке
ферменной нагрузки обязательно присутствует и должно быть нулём.

Статическая нагрузка / совместимый одношаговый импульс:

bcforce_stat
<количество записей>
10,node,Fx,Fy,Mz

В RunStatic тип 10 является постоянной статической нагрузкой. В RunTransient он
сохраняет историческую семантику прямоугольного импульса на первом шаге t=dt.
Дискретный импульс равен F0*dt.

Гармоническая нагрузка:

bcforce_harm
<количество записей>
11,node,Fx,Fy,Mz,frequencyHz

История равна F0*sin(2*pi*frequencyHz*t). Частота должна быть положительной.

Явный одношаговый импульс:

bcforce_pulse
<количество записей>
12,node,Fx,Fy,Mz

Нагрузка записывается только при t=dt; её дискретный импульс равен F0*dt.

Постоянная ступенчатая нагрузка:

bcforce_step
<количество записей>
13,node,Fx,Fy,Mz

Нагрузка действует на всех столбцах истории, включая t=0.

Все записи повторных секций и несколько нагрузок в одном узле суммируются.
Разные временные типы можно прочитать в одну модель, но выбранный решатель должен
поддерживать каждый из них: RunStatic принимает только тип 10.

8. Полный пример рамы

nodes
2
0,0,0
0.5,0,0
elems_113
1
113,1,2,0.0001,2e11,7800,0.33e-8
bcfix
1
1,1,0,0,0
bcforce_stat
1
10,2,0,100,0

В GNU Octave:

problem = StructFEProblem('Case1ElementBeam.txt');
result = problem.RunStatic();
result.displacements
result.reactions
result.elementResults(1).localEndForces

По умолчанию графики и диагностическая печать выключены. Для их включения:

options = struct('verbose', true, 'plotting', true);
problem = StructFEProblem('Case1ElementBeam.txt', options);

9. Модальный и переходный расчёты

problem = StructFEProblem('CaseBeam.txt');
modalResult = problem.RunModal();
modalResult.frequenciesHz

problem = StructFEProblem('CaseBeamDyn.txt');
dynamicResult = problem.RunTransient(1e-4, 1e-2, 3, 2);

Аргументы 3 и 2 означают узел 3 и локальную степень свободы uy. Они проверяются
даже при выключенном plotting. При plotting=true строятся история перемещения и
односторонний амплитудный спектр выбранной степени свободы.

Все переходные истории используют одну сетку: столбец 1 соответствует t=0,
столбец 2 — t=dt, последний — фактической длительности. Число столбцов равно
stepCount+1. Начальные состояния задаются так:

initial = struct('initialDisplacement', u0, 'initialVelocity', v0);
dynamicResult = problem.RunTransient(1e-4, 1e-2, 3, 2, initial);

Начальное ускорение вычисляется из равновесия. Метод Ньюмарка использует
beta=1/4 и gamma=1/2 (средняя акселерация).

10. Результаты и проверки

RunStatic возвращает перемещения, реакции, общий остаток равновесия и
elementResults. Положительные осевая деформация, напряжение и сила означают
растяжение. Для рамы localEndForces имеет порядок
[N1,V1,M1,N2,V2,M2].

RunModal возвращает физические частоты и формы только свободных степеней свободы.
RunTransient возвращает time, loadHistory, displacements, velocities,
accelerations, reactions и спектр.

Полный набор воспроизводимых тестов:

octave --no-gui --quiet --eval "addpath(pwd); run_octave_tests;"
