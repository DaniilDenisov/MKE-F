Chapter 9

From input file to verifiable result

Current MKE-F is a GNU Octave program with a functional numerical core. Model data are created once, solvers return new result structures, and plotting and printing are separate from computation.

Responsibilities

LayerTaskMain code
InputRead sections to EOF, validate records and create elements.FEMesh.m, createStructuralElement.m
AssemblyAccumulate element contributions into sparse global K and M.assembleGlobalMatrices.m
ModelSnapshot of matrices, DOF mapping, supports, loads and element data.createAnalysisModel.m
Numerical coreReduce DOFs, solve and create a new result structure.solveStatic.m, solveModal.m, solveTransient.m
ResultsReactions, equilibrium, local forces and spectrum.calculateStaticEquilibrium.m, recoverElementResults.m, computeSingleSidedSpectrum.m
Compatibility and presentationFamiliar commands RunStatic, RunModal, RunTransient, optional printing and plotting.StructFEProblem.m, plotTransientResult.m

The root function setup adds src/model, src/results, the src/analysis/{common,static,modal,transient} subdirectories and scripts/{runtime,examples,benchmarks/nafems,testing}. The test runner adds tests/octave; for an individual test use addpath(fullfile(pwd, 'tests', 'octave')). Inputs are in examples/cases, ready results in examples/results, and new results go to the Git-ignored output directory.

addpath(pwd);
setup;

problem = StructFEProblem(fullfile( ...
    "examples", "cases", "CaseBeam.txt"));
model = problem.GetAnalysisModel();

staticResult = solveStatic(model);
modalResult = solveModal(model);
Running an analysis through the GUI

Start the container interface from the project root with docker compose up --build or docker-compose up --build. In the preprocessor create a model or open a TXT file containing section analysis and click Run analysis. The backend always calls the fixed RunSelected(); the browser never supplies script names, paths or Octave expressions.

Calling a solver does not change model, problem.K or problem.M. Loads are rebuilt for every run, so repeated analysis and changes in analysis order should not change the result.

Elements and sparse assembly

An element is a plain value structure, not a mutable subclass instance. createStructuralElement creates a common contract for types 112, 113, 1133 and 1436: type, nodeNumbers, properties, a unified vector dofs, matrices and stored length and transformation. The same DOF map is used for assembly and force recovery.

assembleGlobalMatrices first builds row–column–value triplets, then a single call to sparse creates the global matrices. Octave sums contributions at repeated addresses. Memory depends on the number of element coefficients, not the square of the total DOF count.

Architectural invariant

Element mathematics is concentrated in one structure constructor; solvers do not know individual element formulas, and result recovery uses the stored matrices and transformation.

Validation and headless operation

FEMesh checks file opening, section order, field count, finite values, node numbers, element properties, load types and the prohibition on mixed meshes. onCleanup closes the file even on error. Parser messages contain the filename and line; the complete contract is in chapter 10.

By default, verbose=false and plotting=false. Task creation and all three analyses therefore work locally in a terminal without a graphical display. Mesh and history plotting are separate actions; axis equal does not distort mesh geometry.

octave --no-gui --quiet --eval "addpath(pwd); setup; run_octave_tests;"

Verification sequence

  1. run_octave_smoke_tests reads supplied cases, checks sparse assembly and runs available analysis types.
  2. run_verification_tests checks element and global invariants, independent formulas, reactions, loads and call order.
  3. Specialized files check element matrices, assembly, the Mario Paz modal example, Newmark integration, forces and input.
  4. Reference laboratories add educational, executable checks of actual production code.
What is not a reference oracle

The matrices, frequencies and modes of Illustrative Example 11.1 from Mario Paz and William Leigh have been reconstructed and are checked by a dedicated test. Old output snapshots and discrepancies with ANSYS are still not treated as oracles: references are the published example, analytical solutions and explicit invariants.

The 2017 versions and the current program

The author’s articles document project origins but describe the MATLAB architecture of their time. Their class names, breakpoints, matrix mutation order and numerical discrepancies must not be copied into current instructions.
