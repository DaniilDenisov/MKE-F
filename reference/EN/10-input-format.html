Chapter 10

MKE-F input file

The file is a sequence of named text sections. This chapter fully replaces the former root-level guide and matches the current parser FEMesh.

1. Applicability

The program solves linear small-displacement problems in the global plane X–Y:

  • plane trusses made of type 112 members;
  • plane Euler–Bernoulli frames made of type 113 elements;
  • static, modal and undamped transient analyses.
Model limitations

Types 112 and 113 cannot be mixed in one file because their nodes have different DOF counts. Static uniform loads on type 113 frames are supported. Other element loads, nonzero prescribed displacements, plasticity, geometric nonlinearity, damping and frame shear deformation are not implemented.

2. Units

The solver does not convert units. All quantities must form one consistent system; SI is recommended.

QuantityFieldRecommended unit
Coordinates and translational displacementsX, Y, Z, ux, uym
AreaAm²
Young’s modulus and stressE, axialStressPa
Densityrhokg/m³
Second moment of areaIm⁴
ForcesFx, FyN
MomentMzN·m
Time and frequencytime, frequencyHzs, Hz

Coordinate Z is read for format compatibility, but analysis remains two-dimensional. Components uz and Fz do not exist; the third frame-node DOF is rotation thetaZ, with work-conjugate load moment Mz.

3. General syntax rules

The parser reads to EOF. Blank lines and lines whose first non-whitespace character is # are skipped. A normal section marker is followed by an integer record count and exactly that many nonempty data lines. The optional section analysis is an exception and contains a single configuration record.

section_marker
record_count
comma,separated,record
...

Recommended order: analysis, nodes, then elems_112 or elems_113, then bcfix and load sections. Nodes must precede elements; elements must precede supports and loads.

SectionRepeatableRule
analysisNoOptional configuration for RunSelected.
nodesNoExactly one nonempty section.
elems_112 or elems_113YesRecords are appended; the type must be identical across all sections.
bcfixYesRecords are appended; zero records are allowed.
Any bcforce_*YesRecords from all sections are appended and summed when constructing the load.

Fields within a record are comma-separated; surrounding spaces are allowed. Field counts are checked strictly. Numbers must be finite, and IDs and counts must be integers where required.

3.1. Analysis configuration

analysis
static
analysis
modal
analysis
transient,timeStep,duration,monitorNode,monitorDOF

This section is optional for backward compatibility and may appear only once. For transient analysis, the step must be positive, duration must span at least one step, and the monitoring node and local DOF must be within model bounds. RunSelected runs the specified analysis; without the section, use the original explicit methods.

Static analysis allows type 10 nodal loads and type 20 uniform element loads; modal analysis allows no loads; transient analysis allows types 10–13. Type 10 retains its historical single-step pulse meaning in transient analysis.

4. Nodes

nodes
<node count>
X,Y,Z
...

Numbers are assigned by row order: the first record is node 1, the second is node 2. Each row contains exactly three finite numbers. Node numbers are not supplied separately.

5. Elements

TypeSection and recordNodal DOFsModel
112elems_112
112,node1,node2,A,E,rho		[ux,uy]Plane truss member, axial force only.
113elems_113
113,node1,node2,A,E,rho,I		[ux,uy,thetaZ]Plane Euler–Bernoulli frame, consistent mass.

node1 and node2 are distinct integer IDs of existing nodes. A, E, rho, and for type 113 also I must be positive finite numbers. Coincident end coordinates are also rejected as zero length.

Mixed mesh

The first element type determines the DOF count per node. Encountering a different type stops parsing with error MKEF:UnsupportedMixedMesh; truss and frame nodes are not automatically reconciled.

6. Supports

bcfix
<record count>
type,node,0,0,0
typeFreeConstrained
1—All nodal DOFs
2Only uxuy and thetaZ for a frame
3Only uyux and thetaZ for a frame
4thetaZ for a frameux, uy

For a truss node, type 4 equals full restraint because there is no rotational DOF. The last three fields are reserved and must be zero: nonzero prescribed displacements are unsupported. If two records constrain the same global DOF, partitionDOFs reports MKEF:DuplicateConstraint.

7. Nodal loads

A truss uses [Fx,Fy], while a frame uses [Fx,Fy,Mz]. The field Mz is still present in a truss record and must be zero.

Section / typeRecordRunStaticRunTransient
bcforce_stat / 1010,node,Fx,Fy,MzConstant static load.Backward-compatible rectangular pulse only at t=dt; discrete impulse F0·dt.
bcforce_harm / 1111,node,Fx,Fy,Mz,frequencyHzNot supported.F(t)=F0·sin(2πft); f must be strictly positive.
bcforce_pulse / 1212,node,Fx,Fy,MzNot supported.Explicit single-step pulse at t=dt.
bcforce_step / 1313,node,Fx,Fy,MzNot supported.Constant step in every column, including t=0.

Repeated sections, loads at one node and loads mapped to one global DOF are summed. A model may contain different time-dependent types, but the selected solver must support them: RunStatic accepts only type 10 and otherwise reports MKEF:TimeDependentLoadInStaticAnalysis.

9. Annotated transient example

The most informative compact example file is CasePreprocessorTransient.txt. It illustrates analysis configuration, nodes, frame elements, two support types and a harmonic load. The comments below belong to the file and are safe for the parser:

# The input file specifies the analysis used by RunSelected().
analysis
# transient,timeStep,duration,monitorNode,monitorDOF
# Step 0.0001 s, duration 0.001 s; monitor uy (local DOF 2) at node 3.
transient,0.0001,0.001,3,2

# Nodes are numbered by row order. Each record: X,Y,Z.
nodes
3
# Node 1: left end of the beam.
0,0,0
# Node 2: middle of the beam.
1,0,0
# Node 3: right end of the beam.
2,0,0

# Two type 113 Euler–Bernoulli frame elements.
# Format: 113,node1,node2,A,E,rho,I.
elems_113
2
# Element 1 connects nodes 1 and 2.
113,1,2,0.0004,2e11,7800,5.33e-8
# Element 2 connects nodes 2 and 3; properties match element 1.
113,2,3,0.0004,2e11,7800,5.33e-8

# Boundary conditions. Format: type,node,0,0,0.
bcfix
2
# Type 1: ux, uy and thetaZ are constrained at node 1.
1,1,0,0,0
# Type 4: ux and uy are constrained at node 2; thetaZ remains free.
4,2,0,0,0

# Type 11 harmonic nodal load.
# Format: 11,node,Fx,Fy,Mz,frequencyHz.
bcforce_harm
1
# Node 3 has Fy(t) = -1000*sin(2*pi*135*t) N.
11,3,0,-1000,0,135
FragmentHow the program interprets it
transient,0.0001,0.001,3,2Newmark integration takes 10 steps of 0.0001 s and produces 11 states including t=0. The chart and spectrum use uy of node 3.
Three rows after nodesCreate nodes 1–3 on the X axis. There are no separate IDs: the number is the row position.
113,1,2,… and 113,2,3,…Create two frame elements with area 0.0004 m², Young’s modulus 2·10¹¹ Pa, density 7800 kg/m³ and second moment of area 5.33·10⁻⁸ m⁴.
1,1,0,0,0Fully fix node 1: constrain ux, uy and thetaZ.
4,2,0,0,0At node 2, constrain both translational DOFs but leave rotation free: thetaZ.
11,3,0,-1000,0,135Apply a harmonic force at node 3 in the negative direction of Y with amplitude 1000 N and frequency 135 Hz.
Comments do not count toward the declared total

The parser skips blank lines and lines whose first non-whitespace character is #. Thus, after nodes the number 3 means three coordinate rows even if explanatory comments appear between them. Comments must occupy separate lines: trailing comments after numeric records are unsupported.

Run the file without supplying analysis parameters from code:

addpath(pwd);
setup;

problem = StructFEProblem(fullfile( ...
    "examples", "cases", "CasePreprocessorTransient.txt"));
result = problem.RunSelected();

result.time
result.displacements
result.spectrumFrequencyHz
result.displacementAmplitudeSpectrum

10. Modal and transient analyses

problem = StructFEProblem(fullfile( ...
    "examples", "cases", "CaseBeam.txt"));
modalResult = problem.RunModal();
modalResult.frequenciesHz

problem = StructFEProblem(fullfile( ...
    "examples", "cases", "CaseBeamDyn.txt"));
dynamicResult = problem.RunTransient(1e-4, 1e-2, 3, 2);

The last two arguments are node 3 and local DOF 2 (uy) for the optional chart. Their integer values and ranges are validated even with plotting=false. When graphics are enabled, displacement and the selected DOF’s single-sided amplitude spectrum are plotted.

All histories use the grid t = 0, dt, …, N·dt, where N=fix(duration/dt). The first column corresponds to t=0, the last to the actual N·dt; the column count is N+1.

initial = struct( ...
    "initialDisplacement", u0, ...
    "initialVelocity", v0);
dynamicResult = problem.RunTransient(1e-4, 1e-2, 3, 2, initial);

Vectors u0 and v0 have full model size and zeros on constrained DOFs. Initial acceleration is computed from equilibrium. Integration uses Newmark average acceleration with β=1/4 and γ=1/2.

If the file contains section analysis, run the same analysis as result = problem.RunSelected(). A configured transient run uses zero initial displacements and velocities.

Running a file through the GUI

From the repository root, run docker compose up --build (or docker-compose up --build), open http://127.0.0.1:8080/preprocessor/ and load the TXT file with Open TXT. For an old file without section analysis first select the analysis type and, if needed, transient parameters. The button Run analysis serializes the validated model, calls RunSelected() in the Octave container and opens the result without manual file transfer.

12. Input diagnostics

A read error has the form identifier: filename:line: detail. Main identifiers:

IdentifierCause
MKEF:InputFileOpenFailedFile missing, inaccessible or cannot be opened.
MKEF:UnknownInputMarkerUnknown section name or typo.
MKEF:InputSectionOrderAn element precedes nodes, or a support/load precedes elements.
MKEF:DuplicateInputSectionRepeated section nodes or analysis.
MKEF:MalformedInputInvalid field count, nonnumeric/infinite value, record type, node, frequency or properties.
MKEF:UnexpectedEndOfFileDeclared record count exceeds the actual count.
MKEF:IncompleteInputNo nodes or elements.
MKEF:UnsupportedMixedMeshTypes 112 and 113 occur in one file.
MKEF:UnsupportedConstraintValueThe final three fields of bcfix contain a nonzero prescribed displacement.
MKEF:UnsupportedLoadComponentA truss node specifies nonzero Mz.
MKEF:AnalysisLoadMismatchLoad type is incompatible with the configured analysis.
MKEF:MissingAnalysisConfigurationRunSelected was called for an old file without section analysis.
Finding an error

First open the reported line, then check its marker, record count and exact field count. If parsing succeeds but the solver reports singularity, check connectivity and adequate supports rather than syntax.

Uniform element loads

For static analysis of type 113 frames, add section eload_uniform after the elements. After the record count, each line has the form 20,elementId,coordinateSystem,qx,qy. Coordinate system 1 is local, 2 is global XY; intensity is per unit of actual element length. Local x points from the first node to the second; local y is rotated +90° from x.

eload_uniform
1
20,1,2,0,-1000

Sections may repeat; loads on the same element are summed. All values must be finite; two zero components, a missing element, a type 112 element, and modal/transient analysis are rejected. A nodal force or moment may also be specified using the normal section bcforce_stat.

Example: a 2 m cantilever under qY = −1000 N/m. Reactions: Fy = 2000 N, Mz = 2000 N·m; free-end deflection −0.001 m, rotation −0.000666667 rad.

Editing and deletion in the preprocessor

Select a frame element and click Add element load. The Element loads table contains the coordinate system and components. Switching Local/Global converts components while preserving load direction.

Any actual change to element ends, A, E, rho or I removes its distributed loads. Changing node coordinates removes distributed loads from all incident elements, preserving nodal loads and supports. Re-entering the same value removes nothing.

Deleting a node also deletes its elements, their distributed loads and the node’s own conditions. Other nodes remain and references are renumbered. Deleting an element does not delete its nodes. One Undo restores the whole operation. A deleted transient monitoring node must be selected again.
