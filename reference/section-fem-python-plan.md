# План реализации Python-ядра расчёта сечений MKE-F

> Historical record of the implementation available at `f355300`. For the current Python calculation and Docker verification, see [section field diagnostics](EN/08-result-recovery.html#section-fem-title).

Цель первого этапа — получить Python-пакет, который по геометрии профиля, коэффициенту Пуассона и внутренним усилиям восстанавливает напряжения и находит максимум по Мизесу в сечении и по длине элемента. Сетку и решение задач Сен-Венана поручаем `sectionproperties`. За правила восстановления напряжений, поиск пика и статус результата отвечает MKE-F.

Первый этап заканчивается приёмкой пакета **без HTTP API**. Отдельный серверный контейнер — следующий самостоятельный этап. Браузерный JS-решатель сохраняем как средство сверки и для существующей диагностической страницы.

## Исходные данные

[Эксперимент](../scripts/sectionproperties_probe/) выполнен в Docker с `sectionproperties==3.10.2`. На круге Ø2, прямоугольнике 3 × 1 и прямоугольной трубе 3 × 1 со стенкой 0,15 проверены три уровня сетки (исходный и два уточнения). Локальные значения `Tri6.element_stress()` позволили передать поле в существующий JS-поиск. Для смешанного нагружения расхождение пика на мелкой сетке с аналитическим ориентиром составило 0,11 % для круга и 0,09 % для прямоугольника. Для трубы при сгущении вырос сеточный пик во внутреннем углу.

Эксперимент подтверждает способ доступа к полю. До приёмки остаются все пять профилей, независимые случаи нагрузок, сходимость, поиск по длине и ресурсные ограничения. Источники требований — [математическая постановка и допуски](section-fem-methods.md), [ревизия решателя](section-fem-review.md) и [реализация JS](../shared/section-fem/).

## Правила работы

- Все численные, модульные, регрессионные и интеграционные тесты запускать **только в Docker**. Входные примеры, код проверок и версии зависимостей хранить в Git. Сетки, выгрузки полей, замеры и отчёты писать в игнорируемый каталог `output/`.
- Каждый пункт ниже — отдельный локальный коммит после прохождения его проверок. Если пункт разрастается, разделить его по проверяемому результату. Держать реализацию и её тест в одном коммите. **Не выполнять `git push`.**

## Этап 1. Ядро и численная приёмка

### Построение и повторное использование сеток и полей

При первом расчёте типоразмера ядро вызывает генератор `geometry.create_mesh()` из `sectionproperties` для исходной сетки. По мере проверки сходимости оно строит и сохраняет каждый потребовавшийся уровень сгущения. При следующих расчётах ядро берёт готовые уровни из кэша и добавляет более мелкую сетку только тогда, когда сохранённых уровней недостаточно для требуемой точности.

| Что сохраняем | По чему находим запись | Когда используем повторно |
|---|---|---|
| Координаты узлов и связность Tri6 для каждого уровня | Тип профиля, размеры в единых единицах, параметры разбиения контура и области, уровень сгущения и версия генератора | Для всех элементов с той же геометрией и настройками сетки, в том числе при другом коэффициенте Пуассона ν. |
| Три единичных поля от `Vy`, `Vz`, `T` на этом уровне | Ключ сетки, ν, параметры и версия численного решателя | Для элементов и положений по длине с той же сеткой и ν. При смене усилий ядро комбинирует сохранённые поля. При смене ν использует ту же сетку и рассчитывает комплект полей для нового ν, если его ещё нет в кэше. |

Номер стержня, название профиля, длина элемента и текущие усилия не входят в ключи. Сходимость максимума проверять для фактического сочетания усилий по полям сохранённых уровней.

| Коммит | Реализация | Проверка в Docker перед коммитом |
|---|---|---|
| 1. Воспроизводимый эксперимент | Включить оба существующих скрипта эксперимента в контроль версий. Подготовить отдельный тестовый образ Python, зафиксировать версию Python, библиотеки и зависимостей. Добавить команду для полного прогона с чистым каталогом результатов. | Экспортировать девять сеток и прогнать на свежих выгрузках JS-поиск. Повторить сравнение с аналитикой и проверку адаптивного деления. |
| 2. Входные данные и геометрия | Создать пакет `section_solver/`. Описать локальные оси, единицы, порядок `[N,Vy,Vz,T,My,Mz]`, допустимый ν и размеры. Реализовать круг, кольцо, прямоугольник, квадратную и прямоугольную трубы. Для прямоугольных труб задать острые внутренние углы. | Проверить площадь, центр, моменты инерции, отверстия и обработку неверных размеров. На вытянутом прямоугольнике проверить соответствие ширины и высоты осям. |
| 3. Единичные поля сдвига и кручения | Получить `J_FE` и поля от единичных `Vy`, `Vz`, `T` при явном ν материала. Изолировать вызов API библиотеки в одном адаптере. Хранить компоненты в шести локальных узлах каждого элемента. Для ручного `J_model` выводить отличие от `J_FE`. | Интегрированием проверить обе силы и момент каждого поля. Сверить внутреннюю точку с `local_element_stress()`, сохранить обе стороны общего ребра. Проверить изменение поля при смене ν. |
| 4. Напряжения в точке | Реализовать суперпозицию касательных полей. Для продольного напряжения сохранить формулу MKE-F и аналитические свойства профиля. Возвращать компоненты, Мизес и идентификатор элемента. Согласовать поведение на общей границе, в отверстии и вне материала. | По отдельности приложить шесть единичных усилий, затем смешанную нагрузку. Сверить знаки, поворот осей и масштабирование с JS и аналитическими решениями. |
| 5. Поиск максимума на одной сетке | Перенести поэлементный поиск с верхней оценкой по коэффициентам Бернштейна. Возвращать найденное значение, координаты, верхнюю оценку и относительный зазор. Для острых труб при сдвиге или кручении отделять диагностический сеточный пик от глобального максимума со статусом `unavailable`. При чистом растяжении и изгибе сохранить конечный аналитический максимум. | Сравнить Python и штатный JS-поиск **на одном экспортированном поле**. Включить случай, требующий деления треугольника, и обе ветви для трубы. Проверить верхнюю оценку независимой плотной выборкой. |
| 6. Сходимость, кэш и бюджеты | Сравнивать поля в общих физических точках нескольких сеток. Вести отдельные статусы для поля, `J` и пика. Реализовать описанный выше кэш сеток и единичных полей. Ограничить память с учётом сохранённых уровней, размер сетки, время и число делений. Поддержать отмену. | Сверить результаты с кэшем и без него. По числу вызовов генератора и решателя проверить повтор с другими усилиями, смену ν, смену размеров и запрос дополнительного уровня. Проверить статусы `nonconverged`, `resource_limit`, `cancelled` и соблюдение бюджета при попадании в кэш. |
| 7. Максимум по длине элемента | Принять шесть полиномов усилий по `x/L`. Перенести начальные сечения, стационарные точки эпюр, два сгущения и адаптивную оценку по интервалам. Использовать общие единичные поля во всех сечениях. Для фермы сохранить отдельный расчёт по `N/A`. | Проверить максимум на конце и внутри пролёта, смену знака, повёрнутый профиль, полиномы 2D/3D и достижение лимита выборок. Сопоставить максимум и его положение с JS, учесть симметричные равнозначные максимумы. |
| 8. Приёмка ядра | Собрать единый отчёт по пяти профилям. Зафиксировать версии, нагрузки, сетки, время и пиковую память. Сравнивать ресурсы при сопоставимой достигнутой точности. | Прогнать всю матрицу Python, исходные JS-регрессии и независимые эталоны круга, кольца и прямоугольника. Сохранить команды воспроизведения. |

**Критерии приёмки.** Использовать проектные относительные допуски: геометрия — `1e-4`, крутильная постоянная и результирующие усилия — `1e-3`, поля по норме L2 — `5e-3`, конечный пик против независимого эталона — `1e-2`. Для нулевой ожидаемой компоненты нормировать отклонение на характерную силу или момент. Изменение пика должно укладываться в `5e-3` на каждом из двух последовательных сгущений. Зазор поиска внутри готовой сетки и погрешность дискретизации отражать раздельно. Для сингулярного угла критерием служит корректный статус.

## Этап 2. Отдельный сервис после приёмки ядра

1. **Коммит 9 — внутренний HTTP API.** Обернуть принятый пакет в FastAPI. Предусмотреть операции решения сечения, запроса точки, максимума сечения и максимума элемента. Для длительных задач задать очередь, статусы, отмену и лимиты. В Docker сравнить ответы API с прямым вызовом пакета, проверить перегрузку и освобождение ресурсов после отмены.
2. **Коммит 10 — подключение контейнера.** Добавить `section-solver` во внутреннюю сеть Compose и отдельный маршрут Nginx `/api/v1/sections/`. Задать лимиты CPU и памяти. В Docker проверить запрос через Nginx, доступность существующего API стержневого решателя и поведение при недоступности сервиса сечений.

Решение о подключении серверного расчёта к рабочему постпроцессору принимать по итогам численной приёмки и замеров на ресурсах, сопоставимых с VPS.
