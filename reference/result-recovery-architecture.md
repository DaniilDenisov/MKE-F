# Архитектура результатов после перехода на v8

2026-11-05. Итоги завершённого перехода на v8, разработанного в ветке
`codex/result-recovery-operators`.

## Источники данных и оставшиеся вычисления

Решатель владеет расчётной моделью и результатами. JSON v8 — автономный снимок,
из которого просмотрщик получает принятые параметры и операторы. Новое сечение
в редакторе требует пересчёта. Отсутствующие обязательные поля не заменяются
браузерным расчётом; старые JSON v1–v7 требуют пересчёта исходного TXT.
Проверка формата выдаёт `Unsupported format. Recalculate.` без разбора старых
версий. Архивные JSON и отдельные проверки v1–v7 удалены после завершения перехода.

| Вычисление | Владелец и потребитель | Почему остаётся |
|---|---|---|
| Локальные K/M, сборка системы, решение статики/мод/истории | Octave; матрицы динамики экспортируются inline или общей таблицей | Единственная рабочая формулировка элементов; JS не собирает матрицы по E/A/I/J |
| Принятые A/I/J, центр тяжести, крайние волокна | Octave → `element.sectionProperties` | Просмотрщик использует именно свойства собранной модели, включая ручной J |
| Статические N/V/M и экстремумы нормальных напряжений | Octave → коэффициенты и `sectionStress` | JS вычисляет поле в выбранной точке; полный поиск статических максимумов удалён из пути просмотра |
| Предварительные A/I/J | `shared/sections.js`, `spatial-sections.js`; редактор | Мгновенная автономная обратная связь до запуска решателя; намеренная парная реализация |
| Геометрия профиля, контуры, локальные оси, повороты | Общие геометрические функции; редактор, сцена, разрез, SVG | Нужны для изображения, не заменяют принятые свойства |
| Предварительные MPC, освобождения, активные вращательные подпространства и ранг | `mpc.js`, `releases.js`, `spatial-conditions.js`; редактор | Диагностика при вводе и атомарном редактировании; окончательная проверка — Octave |
| Проверка структуры и согласованности v8 | `data-model.js`, `spatial-data.js`, общие валидаторы | Файл может быть повреждён: проверяются размерности, кинематика, свойства и значения в переданных критических точках, без повторного полного поиска экстремумов |
| Преобразование DOF, `K·u`, `M·a`, модальное `a=−λu` | `spatial-results.js`; восстановление динамики 2D/3D | Применение экспортированных операторов к выбранному кадру; это не повторная сборка или решение модели |
| Динамические коэффициенты усилий и поиск экстремумов | `spatial-results.js`, `spatial-stress.js`, `MKEFSpatialSections.stress` | Вычисляются по выбранной моде/кадру; перенос всех полей истории увеличит файл. Знаки и формулы проверяются против Octave |
| Линейная/эрмитова интерполяция перемещений, границы эпюр, масштаб анимации | `geometry.js`, `spatial-results.js`, модули представлений | Рисование с произвольным разрешением; масштаб изображения не изменяет исходные численные результаты |
| Поле нормальных напряжений в точке, крайние значения выбранного разреза | `normal-stress-results.js`, `spatial-normal-stress.js`, `stressField` | Произвольные x/L и точки сечения, разрезы и окраска; общий максимум статики читается из файла |
| Законы отображения нагрузок во времени, преобразования спектра, выборка графика | Модули transient, charts, spatial-results | Визуализация сохранённого отклика; FFT и интегрирование движения остаются у решателя |
| Поле сдвига/кручения и максимум Мизеса | Сервис Python sectionproperties | Отдельная FEM-задача сечения, а не дубль стержневого решателя; JS формирует запрос из геометрии, принятых свойств и усилий |

`MKEFSections.stress` больше не загружается приложением. Независимая прежняя
формула 2D находится только в `scripts/planar-stress-reference.cjs` для сравнения.
Поиск корней остаётся рабочим для динамических экстремумов 3D. Удалять все
арифметические операции из браузера не требуется: важна одна формулировка
решаемой задачи и явные потребители остальных вычислений.

## Явные границы модулей

- `MKEFSections.geometry` проверяет размеры и создаёт примитивы без A/I/J.
  `contours` получает центр тяжести явно и строит границу.
- `properties` — редакторский расчёт. `resultProperties` читает снимок Octave,
  проверяет контракт и добавляет геометрию для рисования.
- `MKEFSpatialSections.catalog` предназначен для редактора, `resultCatalog` —
  для результатов. Скрытого переключения по наличию `model.recovery` нет.
- `MKEFSectionDrawing.preview` обслуживает редактор; `previewResult` требует
  готовые свойства и не имеет запасного пути расчёта.

## Обязательные парные проверки

| Изменение | Проверки в Docker |
|---|---|
| Размеры профиля, округления, ориентация, A/I/J, ручной J | `test_sections`, `test_spatial_sections`, `test_section_contract`: Octave ↔ JS, аналитические случаи, 42 комбинации профилей/углов |
| MPC, освобождения, активные оси, ранг или допуск | `test_spatial_condition_parity` в JS/Octave (22 случая), `test_spatial_conditions`, тесты MPC/освобождений; проверять обе стороны порогов |
| K/M, порядок DOF, знаки N/V/M, восстановление динамики | `test_recovery_operators` (641 кадр), `test_planar_recovery` (1197 кадров), `test_spatial_post`, `test_normal_stress`; аналитические решения дополнительно к межъязыковому совпадению |
| Чтение свойств, статических максимумов, разрез/окраска/CSV/SVG/Мизес | `test_section_contract` и браузерный набор: отключённые формулы свойств и поиска корней, 24 повреждённых контракта |

Численные сравнения используют масштабы соответствующих величин. Изменение
допуска только ради прохождения теста недопустимо. Независимые формулы в тестах
намеренно не удаляются вместе с производственным дублированием.

## Передача чисел

Нативный Octave 11.3 `jsonencode` обнулял некоторые малые ненулевые числа.
Экспорт результатов теперь использует `encodeResultJson`: конечные double
записываются через `%.17g`; строки и логические значения кодируются нативно.
Массивы схемы, включая singleton, сохраняют вложенность. Отрицательный ноль
нормализуется в положительный, как при скачивании через JSON.stringify.

887 побитовых проверок сверяют JavaScript JSON.parse с исходными double Octave:
обычные значения, соседние числа, субнормальные значения, малые K/M, моды и
истории. Масштабирование на 10⁻⁴⁰ — искусственная проверка транспорта, а не
требование точности для обычной модели. Малое число не обязательно существенно,
но сериализатор не знает физических единиц и допустимой погрешности. Обнуление
шума должно быть отдельной осмысленной операцией, не побочным эффектом записи.

Эталоны восстановления берутся из исходного состояния решателя: jsondecode
Octave сам может округлить значение на один ULP и потому не служит эталоном.
Гарантия передачи не устраняет округления, переполнения или плохую
обусловленность внутри расчёта. Четыре готовых примера пересчитаны новым экспортом.

## Замеры ресурсов

Артефакты: `output/recovery-runs/20261105-002047-cc4b8b85`.
Octave 11.3.0; Chromium 156.0.8078.4 в Docker, программный WebGL.
Реальная 2D-консоль содержит 200 элементов, 600 мод, 21 временной отсчёт.
Реальная 3D-рама содержит 80 элементов, освобождение и MPC, 21 отсчёт.
Случай 2D/2000 повторяет записи элемента и использует историю исходной консоли;
он проверяет UI, но не является физическим расчётом 2000 элементов.

|---|---:|---:|---:|---:|---:|
| 2D, 200, статика | 0,27 | 1,10 | 5,6 | 0,33 | — |
| 2D, 200, моды | 7,84 | 0,99 | 25,5 | 2,98 | 18 |
| 2D, 200, история | 1,41 | 0,91 | 7,5 | 0,78 | 23 |
| 3D, 80, статика | 0,20 | 0,89 | 6,8 | 0,33 | — |
| 3D, 80, моды | 1,97 | 1,01 | 12,3 | 1,65 | 58 |
| 3D, 80, история | 0,75 | 0,99 | 7,7 | 0,69 | 3 |
| 2D, 2000, моды, синтетика | 8,64 | — | 35,5 | 4,20 | 17 |

Экспорт — одно наблюдение, чтение/heap — медиана трёх после прогрева.
Heap — прибавка удерживаемого набора после GC с уже загруженной входной строкой;
это не полная память вкладки, рендера или GPU. Время не включает чтение файла,
передачу строки и GC. Число обновлений — наблюдение, не обещание FPS:
3D-история меняет кадр лишь раз в 250 мс при воспроизведении всей истории за 5 с.

Таблица K/M сохраняет пользу: на реальной раме уменьшает JSON на 6,1% для мод
и 14,6% для истории. На синтетических 2000 повторяющихся/смешанных операторах —
на 67,3%; при уникальных операторах auto оставляет inline. После gzip выигрыш
реальной рамы менее 1%, но автономный JSON и удерживаемые матрицы не используют
gzip. Исторический [отчёт](recovery-operator-pooling-measurements.md) сохранён.

## Принятые пределы

Существующие лимиты сохраняются: JSON до 100 MiB в просмотрщике и по умолчанию
в backend; 100 000 узлов/элементов — структурные пределы чтения; 2000 элементов —
мягкая интерактивная цель с уведомлением. Эти пределы не обещают быстрой работы
любой истории или спектра. Число мод/отсчётов и заполненность матриц влияют сильнее
одного количества элементов. Backend по умолчанию ограничивает задачу 30 минутами.

Пространственная сцена ограничивает линии деформации и эпюр бюджетом 1 000 000
вершин на слой, подписи/таблицы — 200 записями, позиции сечений — 600.
Тест синтетической сцены 100 000 элементов проверяет эти ограничения;
динамика проверяется на 2000. Тот же общий бюджет вершин для 2D не заявляется.
Порог 30 с в тесте чтения — диагностика зависания, не SLA.

Повышать лимиты по этим замерам оснований нет. Если на сервере меняется
`MKEF_MAX_RESULT_BYTES`, необходимо отдельно согласовать лимит просмотрщика.
Для большого результата доступны выбор полей/DOF и шаг выгрузки истории;
повышение лимита файла само по себе не решает расход памяти.

## Объём кода и приёмка

Объём рабочего кода, тестов и документации учитывается отдельно. Переформатирование
готовых JSON не считается сокращением расчётной логики. Тестовый независимый
расчёт остаётся в репозитории, но исключён из приложения. Сериализатор добавляет
рабочий код для сохранения чисел; это отдельное исправление, а не новый дубль
формулировки элемента.

Изменение строк относительно предыдущего этапа (`ac32742`), включая комментарии
и пустые строки; готовые JSON вынесены отдельно:

| Категория | Добавлено | Удалено | Разница |
|---|---:|---:|---:|
| Рабочий код | 119 | 66 | +53 |
| Тесты и их запуск | 166 | 25 | +141 |
| Документация | 268 | 22 | +246 |
| Готовые JSON | 218 | 6320 | −6102 |

Из +53 строк рабочего кода 60 приходятся на новый сериализатор; остальные
изменения в сумме дают −7 строк. Главное упрощение — удалённый рабочий расчёт
и явные границы, а не размер файлов. Большое сокращение строк JSON связано
с компактной записью числовых рядов при prettyPrint и не означает удаление данных.

Все проверки выполнены в Docker. Основной запуск создал свежие данные Octave;
после исправления длительности наблюдения анимации повторно прошли все 14
JS/браузерных наборов на этих данных (`recovery/PASS.json`). Дополнительно прошли
72 модульных браузерных теста и 72 теста backend. Пересобранный временный стек
`output/mkef-v8-d591c5c9` прошёл восемь API/браузерных сценариев, четыре готовых
примера и отказ для v1–v7; стек удалён. Production не обновлялся.
Справочник: 44 страницы RU/EN, перенаправления и браузерные примеры прошли проверку.
