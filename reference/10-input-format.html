Входной файл МКЭ‑Ф

Файл — последовательность именованных текстовых секций. Этот раздел полностью заменяет прежнее корневое руководство и соответствует текущему парсеру FEMesh.

1. Область применения

Программа решает линейные задачи малых перемещений в глобальной плоскости X–Y:

  • плоские фермы из стержней типа 112;
  • плоские рамы Эйлера–Бернулли из элементов типа 113;
  • статический, модальный и недемпфированный переходный расчёты.
Границы модели

В одном файле нельзя смешивать типы 112 и 113: у их узлов разное число СС. Не реализованы распределённые нагрузки, ненулевые заданные перемещения, пластичность, геометрическая нелинейность, демпфирование и деформация сдвига рамного элемента.

2. Единицы

Решатель не преобразует единицы. Все величины должны образовывать одну согласованную систему; рекомендуется СИ.

Координата Z читается для совместимости формата, но расчёт остаётся двумерным. Компонент uz и Fz нет; третья СС рамного узла — поворот thetaZ, а сопряжённая нагрузка — момент Mz.

3. Общие правила синтаксиса

Парсер читает файл до конца. Пустые строки и строки, первый непробельный символ которых #, пропускаются. После обычного маркера секции идёт целое число записей, затем ровно столько непустых строк данных. Необязательная секция analysis является исключением и содержит одну конфигурационную запись.

section_marker
record_count
comma,separated,record
...

Рекомендуемый порядок: analysis, nodes, затем elems_112 или elems_113, затем bcfix и секции нагрузок. Узлы обязаны предшествовать элементам, элементы — опорам и нагрузкам.

СекцияМожно повторятьПравило
analysisНетНеобязательная конфигурация для RunSelected.
nodesНетРовно одна непустая секция.
elems_112 или elems_113ДаЗаписи добавляются; тип во всех секциях должен совпадать.
bcfixДаЗаписи добавляются; допустимо ноль записей.
Любая bcforce_*ДаЗаписи всех секций добавляются и при построении нагрузки суммируются.

Поля внутри записи разделяются запятыми; пробелы около значения допустимы. Количество полей проверяется строго. Числа должны быть конечными, а идентификаторы и количества — целыми там, где это требуется.

3.1. Конфигурация расчёта

analysis
static
analysis
modal
analysis
transient,timeStep,duration,monitorNode,monitorDOF

Секция необязательна для обратной совместимости и может появиться только один раз. Для переходного расчёта шаг времени положителен, длительность покрывает хотя бы один шаг, а контрольный узел и локальная СС находятся в диапазоне модели. RunSelected запускает указанный расчёт; без секции следует использовать прежние явные методы.

Статика допускает только нагрузки типа 10, модальный расчёт — ни одной нагрузки, переходный расчёт — типы 10–13. Тип 10 в переходной задаче сохраняет историческую семантику одношагового импульса.

4. Узлы

nodes
<количество узлов>
X,Y,Z
...

Номера назначаются порядком строк: первая запись — узел 1, вторая — узел 2. Каждая строка содержит ровно три конечных числа. Номер узла в файле отдельно не задаётся.

5. Элементы

ТипСекция и записьУзловые ССМодель
112elems_112
112,node1,node2,A,E,rho		[ux,uy]Плоский ферменный стержень, только осевая сила.
113elems_113
113,node1,node2,A,E,rho,I		[ux,uy,thetaZ]Плоская рама Эйлера–Бернулли, согласованная масса.

node1 и node2 — различные целые номера существующих узлов. A, E, rho, а для типа 113 и I должны быть положительными конечными числами. Совпадающие координаты концов также отклоняются как нулевая длина.

Смешанная сетка

После первого типа элемента число СС на узел уже определено. Встреча другого типа завершает чтение ошибкой MKEF:UnsupportedMixedMesh; автоматического согласования ферменного и рамного узла нет.

6. Опоры

bcfix
<количество записей>
type,node,0,0,0
typeСвободноЗакреплено
1—Все СС узла
2Только uxuy и thetaZ у рамы
3Только uyux и thetaZ у рамы
4thetaZ у рамыux, uy

У ферменного узла тип 4 совпадает с полным закреплением, поскольку поворотной СС нет. Последние три поля зарезервированы и обязаны равняться нулю: ненулевые заданные перемещения не поддерживаются. Если две записи закрепляют одну глобальную СС повторно, partitionDOFs сообщает MKEF:DuplicateConstraint.

7. Узловые нагрузки

У фермы используются [Fx,Fy], у рамы — [Fx,Fy,Mz]. Поле Mz в ферменной записи всё равно присутствует и должно быть нулём.

Секция / типЗаписьRunStaticRunTransient
bcforce_stat / 1010,node,Fx,Fy,MzПостоянная статическая нагрузка.Исторически совместимый прямоугольный импульс только при t=dt; дискретный импульс F0·dt.
bcforce_harm / 1111,node,Fx,Fy,Mz,frequencyHzНе поддерживается.F(t)=F0·sin(2πft); f строго положительна.
bcforce_pulse / 1212,node,Fx,Fy,MzНе поддерживается.Явный одношаговый импульс при t=dt.
bcforce_step / 1313,node,Fx,Fy,MzНе поддерживается.Постоянная ступень во всех столбцах, включая t=0.

Повторные секции, нагрузки в одном узле и нагрузки, попавшие в одну глобальную СС, суммируются. В одной модели можно прочитать разные временные типы, но выбранный решатель обязан их поддерживать: RunStatic принимает только тип 10 и иначе выдаёт MKEF:TimeDependentLoadInStaticAnalysis.

9. Аннотированный переходный пример

Наиболее содержательный компактный файл в каталоге примеров — CasePreprocessorTransient.txt. Он показывает конфигурацию расчёта, узлы, рамные элементы, два типа закрепления и гармоническую нагрузку. Комментарии ниже входят в сам файл и безопасны для парсера:

# Вид расчёта задаётся во входном файле и используется методом RunSelected().
analysis
# transient,timeStep,duration,monitorNode,monitorDOF
# Шаг 0.0001 с, длительность 0.001 с; контролируется uy (локальная СС 2) узла 3.
transient,0.0001,0.001,3,2

# Узлы нумеруются порядком строк. Формат каждой записи: X,Y,Z.
nodes
3
# Узел 1: левый конец балки.
0,0,0
# Узел 2: середина балки.
1,0,0
# Узел 3: правый конец балки.
2,0,0

# Два рамных элемента Эйлера–Бернулли типа 113.
# Формат: 113,node1,node2,A,E,rho,I.
elems_113
2
# Элемент 1 соединяет узлы 1 и 2.
113,1,2,0.0004,2e11,7800,5.33e-8
# Элемент 2 соединяет узлы 2 и 3; свойства совпадают с элементом 1.

# Граничные условия. Формат: type,node,0,0,0.

# Тип 1: в узле 1 закреплены ux, uy и thetaZ.

# Формат: 11,node,Fx,Fy,Mz,frequencyHz.

ФрагментКак его интерпретирует программа
transient,0.0001,0.001,3,2Метод Ньюмарка делает 10 шагов по 0,0001 с и формирует 11 состояний вместе с t=0. Для графика и спектра выбирается uy узла 3.
Три строки после nodesСоздают узлы 1–3 на оси X. Отдельных идентификаторов в записи нет: номер равен позиции строки.
113,1,2,… и 113,2,3,…Создают два рамных элемента с площадью 0,0004 м², модулем Юнга 2·10¹¹ Па, плотностью 7800 кг/м³ и моментом инерции 5,33·10⁻⁸ м⁴.
1,1,0,0,0Полная заделка узла 1: закреплены ux, uy и thetaZ.
4,2,0,0,0В узле 2 закреплены обе поступательные СС, но оставлен свободным поворот thetaZ.

Комментарии не входят в объявленное количество

Парсер пропускает пустые строки и строки, у которых первый непробельный символ — #. Поэтому после nodes число 3 означает три строки координат, хотя между ними находятся пояснения. Комментарий должен занимать отдельную строку: комментарии в конце числовой записи форматом не предусмотрены.

Файл можно выполнить без передачи параметров анализа из кода:

setup;

problem = StructFEProblem(fullfile( ...
    "examples", "cases", "CasePreprocessorTransient.txt"));
result = problem.RunSelected();

result.displacements
result.spectrumFrequencyHz
result.displacementAmplitudeSpectrum

10. Модальный и переходный расчёты

problem = StructFEProblem(fullfile( ...
    "examples", "cases", "CaseBeam.txt"));
modalResult = problem.RunModal();
modalResult.frequenciesHz

problem = StructFEProblem(fullfile( ...
    "examples", "cases", "CaseBeamDyn.txt"));
dynamicResult = problem.RunTransient(1e-4, 1e-2, 3, 2);

Последние два аргумента — узел 3 и локальная СС 2 (uy) для необязательного графика. Их целочисленность и диапазон проверяются даже при plotting=false. При включённой графике строятся перемещение и односторонний амплитудный спектр выбранной СС.

Все истории используют сетку t = 0, dt, …, N·dt, где N=fix(duration/dt). Первый столбец соответствует t=0, последний — фактическому N·dt; число столбцов равно N+1.

initial = struct( ...
    "initialDisplacement", u0, ...
    "initialVelocity", v0);
dynamicResult = problem.RunTransient(1e-4, 1e-2, 3, 2, initial);

Векторы u0 и v0 имеют полный размер модели и нули на закреплённых СС. Начальное ускорение вычисляется из равновесия. Интегрирование использует метод средних ускорений Ньюмарка с β=1/4 и γ=1/2.

Если файл содержит секцию analysis, тот же расчёт запускается как result = problem.RunSelected(). Настроенный переходный запуск использует нулевые начальные перемещения и скорости.

Запуск файла через GUI

Выполните из корня репозитория docker compose up --build (или docker-compose up --build), откройте http://127.0.0.1:8080/preprocessor/ и загрузите TXT-файл кнопкой Open TXT. Для старого файла без секции analysis сначала выберите вид расчёта и, при необходимости, параметры переходного процесса. Кнопка Run analysis сериализует проверенную модель, вызывает RunSelected() в контейнере Octave и открывает результат без ручного переноса файлов.

12. Диагностика входа

Ошибка чтения имеет вид identifier: filename:line: detail. Основные идентификаторы:

ИдентификаторПричина
MKEF:InputFileOpenFailedФайл не найден, недоступен или не может быть открыт.
MKEF:UnknownInputMarkerНеизвестное имя секции или опечатка.
MKEF:InputSectionOrderЭлемент встретился до узлов либо опора/нагрузка — до элементов.
MKEF:DuplicateInputSectionПовторена секция nodes или analysis.
MKEF:MalformedInputНеверное число полей, нечисловое/бесконечное значение, тип записи, узел, частота или свойства.
MKEF:UnexpectedEndOfFileОбъявленное число записей больше фактического.
MKEF:IncompleteInputНет узлов или элементов.
MKEF:UnsupportedMixedMeshВ одном файле встретились типы 112 и 113.
MKEF:UnsupportedConstraintValueВ последних трёх полях bcfix есть ненулевое заданное перемещение.
MKEF:UnsupportedLoadComponentДля ферменного узла задан ненулевой Mz.
MKEF:AnalysisLoadMismatchТип нагрузки несовместим с настроенным видом расчёта.
MKEF:MissingAnalysisConfigurationRunSelected вызван для старого файла без секции analysis.
Как искать ошибку

Сначала откройте указанную строку файла, затем проверьте маркер, число записей и точное количество полей. Если парсер прошёл, но решатель сообщил сингулярность, проверяйте уже не синтаксис, а связность и достаточность опор.

13. Код, тесты и источники

  • FEMesh.m — единственный действующий контракт синтаксического разбора;
  • preprocessor/index.html — автономный редактор с координатной сеткой, точным вводом узлов и каноническим экспортом файлов этого формата;
  • tests/test_input_validation.m — повторные секции, неверные записи, смешанная сетка, неизвестный маркер, открытие и выбор графика;
  • CaseRepeatedSections.txt — исполняемый пример повторных секций;
  • Henri P. Gavin, Numerical Integration in Structural Dynamics — внешний материал по схеме Ньюмарка;
  • Mario Paz, William Leigh, Structural Dynamics: Theory and Computation, 5-е изд., 2004, DOI 10.1007/978-1-4615-0481-8 — источник геометрии, матриц, частот и форм CaseFig11.7p363 MarioPaz.txt, проверяемых в tests/test_mario_paz_modal.m.
