## Цель и принятый подход

Облегчить проект за счёт удаления исторических форматов, обходных путей чтения,
исключений редактора и интерфейсов, которые обслуживаются только ради старых
данных. Удалять соответствующие тесты вместе с ненужным поведением, сохраняя
проверки актуальных расчётов и операций пользователя.

- Поддерживается текущий контракт результатов v8. Автоматическая конвертация,
  миграционные адаптеры и отдельные наборы архивных файлов не нужны.
- Для несовместимого формата достаточно `Unsupported format. Recalculate.`
  Ошибки текущей модели — например, неподдерживаемое сечение — должны сохранять
  конкретную причину: один пересчёт не исправит такие входные данные.
- Канонические файлы проекта обновляются один раз вместе с кодом. Не создавать
  постоянный конвертер, архив старых эталонов или новые тесты для каждой удалённой
  версии/формы записи.
- Пользователь явно разрешил переписать примеры на актуальный формат.
  Сохранение старого текста примера или старого API не является целью.
  **Лабораторные — важная часть продукта: их работоспособность и учебный смысл
  должны полностью сохраниться.** Переписывать их входные файлы и внутренние
  вызовы можно вместе с примерами, удалять задания ради очистки нельзя.
- Не менять физическую постановку под видом очистки. В частности, старый импульс
  нельзя заменить постоянной нагрузкой, а смешанные вращения — физическими DOF.
- Не вводить новый номер формата только ради этой очистки. Уточнить обязательные
  поля текущего v8 и документацию; экспериментальные неполные файлы не поддерживать.

## Порядок работы в следующем диалоге

1. Прочитать этот файл, проверить текущие инструкции репозитория, ветку и diff.
   Изменения пользователя не перезаписывать. Идентификаторы коммитов и числа ниже
   относятся к моменту исследования, а не заменяют проверку текущего состояния.
2. Создать рабочую ветку от актуального `master`, например `codex/legacy-cleanup`.
3. Выполнять этапы по очереди. У каждого этапа сначала установить действующих
   потребителей, затем удалить старую ветку поведения и обновить её потребителей.
4. Все исполняемые проверки — только в Docker. Сначала затронутые наборы, общий
   конвейер и runtime-стек — при итоговой приёмке. Не перепроверять неизменённое
   после каждого документационного исправления.
5. Обновлять чекбоксы и фиксировать реальные результаты. Не делать merge, push
   или обновление рабочего сервера без соответствующего поручения.

- Чтение текущих `bcfix` через числовые записи и `normalizeSupports`: этим
  пользуются `FEMesh`, `createAnalysisModel`, `supportType`. При желании держать
  внутри ядра только маски преобразование должно остаться на границе импорта.
  Не менять каталог закреплений ради удаления комментария `legacy`.
- Непоследовательные ID, отсутствие необязательного блока освобождений,
  повторяемые блоки нагрузок и выборочный экспорт действующих полей.
- Определение 2D/3D по типу элемента, а не по наличию ненулевого Z. Отдельная
  политика запрета Z у плоских элементов — изменение входного контракта,
  не обязательная часть этой очистки.
- `model.recovery.version` 1/2 — inline/table в текущем v8;
  `consistent-v1` и версия реестра типов элементов не означают JSON v1.
- Актуальные операции Undo/Redo, диагностику MPC/освобождений, отсутствие
  WebGL и сетевых сервисов, независимые аналитические/межъязыковые сравнения.
- Локализацию справочника и рабочие страницы. Старые URL-перенаправления —
  совместимость ссылок, не моделей. Их возможное удаление вынести отдельно:
  проверить ссылки, удалить именно страницы-переадресации и их тесты, сохранить
  RU/EN, выбор языка и реальные лабораторные. Не удалять весь корень `reference/`.

действующие проверки текущего контракта и аналитические задачи. Не ослаблять
численные допуски, не менять физический эталон ради прохождения теста.
