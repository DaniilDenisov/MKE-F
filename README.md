# МКЭ-Ф

Учебная программа на GNU Octave для расчета плоских ферм и рам
методом конечных элементов.

https://конструкторский.рф/

## GNU Octave

Минимальная целевая версия — GNU Octave 8.4. Локально программа проверяется
на GNU Octave 11.3.0.

GNU Octave является единственной поддерживаемой средой выполнения. Совместимость
с MATLAB не тестируется и не гарантируется.

## Единый интерфейс через Docker Compose

Препроцессор, расчёт в GNU Octave 11.3.0 и постпроцессор можно запустить как
единое локальное приложение. Установленный на компьютере Octave для этого не
нужен — требуется Docker Desktop или Docker Engine с Compose:

```sh
docker compose up --build
```

Для старой отдельной команды Compose используется эквивалентный запуск
`docker-compose up --build`. После готовности контейнеров откройте
`http://127.0.0.1:8080`. Кнопка `Run analysis` передаёт текущую проверенную
модель локальному API, показывает состояние и журнал Octave, а после расчёта
автоматически открывает результат. JSON результата нужно скачать, если его
требуется сохранить после остановки контейнеров.

Снаружи публикуется только Nginx на loopback-интерфейсе. FastAPI и Octave
доступны лишь во внутренней сети Compose; произвольные скрипты и выражения API
не принимает. Одновременно выполняется один расчёт. По умолчанию действуют
тайм-аут 30 минут, лимиты 10 МиБ для кейса и 100 МиБ для результата. Порт и
основные лимиты можно переопределить переменными `MKEF_PORT`,
`MKEF_JOB_TIMEOUT_SECONDS`, `MKEF_SOLVER_CPUS` и `MKEF_SOLVER_MEMORY`.

Проверка контейнерного стека после запуска:

```powershell
./scripts/compose_smoke_test.ps1
```

Сборка и запуск Python/Octave интеграционных тестов в отдельном тестовом образе:

```sh
docker build --target test -t mkef-solver-test -f docker/solver.Dockerfile .
docker run --rm mkef-solver-test
```

Прямое открытие `preprocessor/index.html` и `postprocessor/index.html` с диска
по-прежнему поддерживается; в этом режиме доступны прежние операции с файлами,
но запуск расчёта отключён.

Перед работой добавьте корень репозитория в путь и подключите каталоги исходного
кода:

```octave
addpath(pwd);
setup;
```

Запуск полного набора тестов без графического интерфейса:

```sh
octave --no-gui --quiet --eval "addpath(pwd); setup; run_octave_tests;"
```

Запуск только быстрого smoke-теста:

```sh
octave --no-gui --quiet --eval "addpath(pwd); setup; run_octave_smoke_tests;"
```

## Структура проекта

- `src/model` — чтение модели, элементы и сборка глобальных матриц;
- `src/analysis` — общие операции и отдельные статический, модальный и
  переходный решатели;
- `src/results` — восстановление результатов, экспорт и графики;
- `preprocessor` — автономное создание и редактирование входных файлов;
- `postprocessor` — автономный просмотр результатов расчёта;
- `examples/cases` — поставляемые входные модели, а `examples/results` —
  готовые JSON-примеры для постпроцессора;
- `scripts` — точки запуска тестов;
- `tests/fixtures` — данные только для проверок ошибок и граничных случаев.

Каталог `output` предназначен для новых результатов и не отслеживается Git.
Функция `setup` подключает `src` и `scripts` явным списком каталогов; имена
публичных функций после инициализации не меняются.

## Автономный учебный справочник

Полный русскоязычный справочник начинается с
[`reference/index.html`](reference/index.html). Его можно открыть прямо с диска:
все стили и материалы находятся в репозитории, подключение к интернету для
чтения и выполнения лабораторных не требуется.

Полный численный разбор двухэлементной рамы Mario Paz — от локальных матриц
жёсткости и масс до частот и форм — находится в
[`reference/11-mario-paz-modal-example.html`](reference/11-mario-paz-modal-example.html).

Отдельный путь для студентов с установленным GNU Octave, но без Docker и
браузерного GUI, приведён в
[`reference/12-local-octave-workflow.html`](reference/12-local-octave-workflow.html):
там показаны `RunSelected`, явные методы анализа, чистые функции ядра и локальные
smoke- и verification-тесты.

Все семь лабораторных используют функции проекта, проверяют численные инварианты
и запускаются из корня репозитория одной командой GNU Octave:

```octave
addpath(pwd);
setup;
addpath(fullfile(pwd, 'reference', 'examples'));
results = run_reference_examples();
```

Для тихого запуска без печати матриц передайте `false`:
`run_reference_examples(false)`. Эта проверка также входит в обычный
локальный запуск `run_octave_tests`.

По умолчанию задача создаётся без графиков и диагностической печати:

```octave
problem = StructFEProblem(fullfile('examples', 'cases', ...
    'Case1ElementBeam.txt'));
staticResult = problem.RunStatic();
```

Их можно включить явно:

```octave
options = struct('verbose', true, 'plotting', true);
problem = StructFEProblem(fullfile('examples', 'cases', ...
    'Case1ElementBeam.txt'), options);
```

Методы `RunStatic`, `RunModal` и `RunTransient` возвращают структуры с явно
названными результатами и не изменяют собранные матрицы `K` и `M` или старое
совместимое поле `F`. Численное ядро можно вызывать без печати и графиков:

```octave
model = problem.GetAnalysisModel();
staticResult = solveStatic(model);
modalResult = solveModal(model);
dynamicResult = solveTransient(model, ...
    struct('timeStep', 1e-4, 'duration', 1e-2));
```

Опоры преобразуются в списки `fixedDOFs` и `freeDOFs`. Решатели работают с
редуцированными матрицами свободных степеней свободы, а возвращаемые полные
векторы и формы колебаний содержат точные нули на закреплённых степенях свободы.
Статический результат также содержит реакции и невязку общего равновесия
`equilibriumResidual = [Fx; Fy; Mz]`.

## Автономный препроцессор

Откройте [`preprocessor/index.html`](preprocessor/index.html) прямо с диска.
Препроцессор не требует сервера или подключения к сети: узлы и элементы можно
создавать на SVG-поле, а точные координаты, свойства, опоры и нагрузки — менять
в таблицах. Существующий `.txt`-файл открывается через `Open TXT` или
перетаскиванием, после чего сохраняется в каноническом порядке секций.
Поле показывает оси X/Y и координатную сетку. Новые узлы по умолчанию
привязываются к ней; общий размер сетки и шага привязки задаётся в панели
`Canvas tool`. Координаты выбранного узла можно ввести непосредственно в панели
`Selection` или в полной таблице узлов.

Выбранный тип расчёта записывается в необязательную секцию `analysis`:

```text
analysis
static
```

```text
analysis
modal
```

```text
analysis
transient,0.0001,0.01,3,2
```

Для переходного расчёта последние четыре поля — шаг времени, запрошенная
длительность, номер контрольного узла и его локальная степень свободы.
Подготовленный файл можно выполнить одной командой:

```octave
problem = StructFEProblem(fullfile('examples', 'cases', ...
    'CasePreprocessorTransient.txt'));
result = problem.RunSelected();
```

Старые файлы без `analysis` остаются совместимыми: для них по-прежнему явно
вызываются `RunStatic`, `RunModal` или `RunTransient`.

## Единицы и допущения модели

Программа не назначает систему единиц: все входные величины должны быть заданы
согласованно. Например, при использовании СИ координаты задаются в метрах,
площадь `A` — в м², модуль Юнга `E` — в Па, плотность `rho` — в кг/м³,
момент инерции `I` — в м⁴, силы — в Н, моменты — в Н·м, время — в секундах,
частота — в Гц. Тогда перемещения получаются в метрах, напряжения — в Па.

Постпроцессор показывает исходные численные значения без преобразования единиц.
Поэтому для модели в СИ координаты и перемещения в постпроцессоре выражены в
метрах, силы (включая нагрузки, реакции и осевые усилия) — в ньютонах, моменты —
в Н·м, а напряжения — в Па. Обозначения единиц берутся из `metadata.units`
экспортированного JSON-файла и должны соответствовать единицам исходной модели.
Исключение — нормированные собственные формы: их амплитуда произвольна и не
является физическим перемещением в метрах.

Поддерживается линейная задача малых перемещений в плоскости `X-Y`:

- элемент `112` — плоский стержень, работающий только на растяжение/сжатие;
- элемент `113` — плоский элемент рамы Эйлера–Бернулли без деформации сдвига;
- используются согласованные матрицы масс, демпфирование отсутствует;
- нагрузки прикладываются только в узлах, заданные перемещения равны нулю;
- один файл должен содержать только один тип элементов; смешанные сетки
  ферма/рама явно отклоняются.

## Модальный вид постпроцессора

Результат модального расчёта можно экспортировать в JSON и открыть локально в
[`postprocessor/index.html`](postprocessor/index.html):

Готовые примеры для всех трёх видов расчёта находятся в
[`examples/results`](examples/results). Новые результаты примеров записываются
в каталог `output`, содержимое которого не отслеживается Git.

```octave
problem = StructFEProblem(fullfile('examples', 'cases', 'CaseBeam.txt'));
model = problem.GetAnalysisModel();
modalResult = problem.RunModal();

exportPostprocessorData(model, modalResult, ...
    fullfile('output', 'modal-frame.json'), ...
    struct('title', 'Формы колебаний', 'lengthUnit', 'm', ...
           'timeUnit', 's', 'prettyPrint', true));
```

Модальный вид позволяет выбирать формы, переходить к предыдущей или следующей
форме, запускать колебание между отрицательным и положительным пиками и вручную
задавать фазовый множитель `q` от `-1` до `+1`. Скорость анимации служит только
для наглядности и не равна показанной собственной частоте. При экспорте SVG или
PNG сохраняется именно текущая видимая фаза вместе с номером формы, частотой и
масштабом изображения.

## Переходный вид постпроцессора

Переходный результат экспортируется тем же способом и открывается локально в
[`postprocessor/index.html`](postprocessor/index.html):

```octave
problem = StructFEProblem(fullfile('examples', 'cases', 'CaseBeam.txt'));
model = problem.GetAnalysisModel();
transientResult = problem.RunTransient(1e-4, 1e-2, 3, 2);

exportPostprocessorData(model, transientResult, ...
    fullfile('output', 'transient-history.json'), ...
    struct('title', 'Переходный отклик', 'lengthUnit', 'm', ...
           'forceUnit', 'N', 'momentUnit', 'N*m', 'timeUnit', 's', ...
           'transientFields', {{'displacements', 'velocities', ...
                                'accelerations', 'loadHistory', ...
                                'reactions', 'spectrum'}}, ...
           'timeStride', 1, 'prettyPrint', true));
```

В окне можно выбрать узел, степень свободы и величину, исследовать историю или спектр,
перейти к точному отсчёту ползунком или щелчком по графику, а также запустить анимацию. Масштаб
деформации определяется один раз для всей истории, поэтому амплитуды между кадрами сравнимы. `Frame stride`
управляет шагом просмотра; он не восстанавливает отсчёты, удалённые при экспорте опцией `timeStride`.
При таком прореживании или при отсутствии необязательных полей интерфейс показывает явное сообщение.

SVG и PNG фиксируют текущий кадр, график, время, номер отсчёта, выбранную величину и масштаб.
Переходные `reactions` — это полный динамический остаток `M*a + K*u - F`; опорными реакциями являются его строки
для закреплённых степеней свободы.

Затем откройте
`http://localhost:8000/postprocessor/tests/` и
`http://localhost:8000/preprocessor/tests/`, а также
`http://localhost:8000/shared/tests/`. Сервер остановится после нажатия

## Формат входного файла

Файл читается до конца. Пустые строки и строки, начинающиеся с `#`, пропускаются.
Обычная секция начинается с маркера, затем идёт целое число записей и сами записи;
необязательная секция `analysis` содержит одну конфигурационную строку.
После неё должны находиться `nodes`, затем одна или несколько секций одного типа
элементов, после них — опоры и нагрузки. Повторные секции `bcfix` и нагрузки
добавляются, а не заменяют ранее прочитанные записи.

```text
nodes
2
0,0,0
0.5,0,0
elems_113
1
113,1,2,0.0001,2e11,7800,0.33e-8
bcfix
1
1,1,0,0,0
bcforce_stat
1
10,2,0,100,0
```

Форматы элементов:

- `elems_112`: `[112,node1,node2,A,E,rho]`;
- `elems_113`: `[113,node1,node2,A,E,rho,I]`.

Номера узлов — целые числа от `1` до количества узлов; два конца элемента должны
быть различны. Ошибки формата содержат имя файла и номер строки.

Строка опоры имеет формат `[type,node,0,0,0]`. Поддерживаются типы:

- `1`: закрепить все степени свободы;
- `2`: оставить свободной только `ux` (`uy` и рамный поворот `thetaZ` закреплены);
- `3`: оставить свободной только `uy` (`ux` и рамный поворот `thetaZ` закреплены);
- `4`: для рамы оставить свободной только `thetaZ`.

Ненулевые заданные перемещения пока не поддерживаются. Подробная спецификация и
дополнительные примеры приведены в
[`reference/10-input-format.html`](reference/10-input-format.html).

## Узловые нагрузки

Для плоской фермы узловая нагрузка имеет компоненты `[Fx, Fy]`. Для плоской
рамы компоненты `[Fx, Fy, Mz]` соответствуют степеням свободы `[ux, uy, θz]`;
силы `Fz` в двумерной модели нет.

- `bcforce_stat`, тип `10`: статическая нагрузка в `RunStatic`; в
  `RunTransient` сохраняет старое значение однократного прямоугольного импульса
  на первом шаге, с дискретным импульсом `F0*dt`.
- `bcforce_harm`, тип `11`: гармоническая нагрузка `F0*sin(2*pi*f*t)`.
- `bcforce_pulse`, тип `12`: явно заданный однократный импульс на первом шаге.
- `bcforce_step`, тип `13`: постоянная ступенчатая нагрузка на всех шагах.

Несколько строк нагрузки в одном блоке суммируются, в том числе если они
относятся к одному узлу или одной степени свободы.

## Переходный расчёт

Все возвращаемые истории используют одну временную сетку: столбец 1
соответствует `t=0`, столбец 2 — `t=dt`, последний столбец — фактической
длительности расчёта. Это относится к `time`, `loadHistory`, `displacements`,
`velocities` и `accelerations`.

Начальные перемещения и скорости можно передать численному ядру:

```octave
transientOptions = struct(...
    'timeStep', 1e-4, ...
    'duration', 1e-2, ...
    'initialDisplacement', u0, ...
    'initialVelocity', v0);
result = solveTransient(model, transientOptions);
```

Или через совместимый фасад:

```octave
initial = struct('initialDisplacement', u0, 'initialVelocity', v0);
result = problem.RunTransient(1e-4, 1e-2, 2, 1, initial);
```

Начальное ускорение вычисляется из равновесия. Результат также содержит
`reactions`, `equilibriumResidual`, `spectrumFrequencyHz` и
`displacementAmplitudeSpectrum`. Используется метод средних ускорений Ньюмарка
(`beta=1/4`, `gamma=1/2`) по формулам (22)-(23) из конспекта
[H. P. Gavin, Numerical Integration in Structural Dynamics](https://people.duke.edu/~hpgavin/StructuralDynamics/NumericalIntegration.pdf).

## Воспроизводимые примеры

```octave
% Статика: консоль с силой 100 Н.
beam = StructFEProblem(fullfile('examples', 'cases', ...
    'Case1ElementBeam.txt'));
staticResult = beam.RunStatic();
staticResult.displacements(5) % FL^3/(3EI)
staticResult.reactions(2:3)   % [-F; -F*L]

% Собственные частоты.
frame = StructFEProblem(fullfile('examples', 'cases', 'CaseBeam.txt'));
modalResult = frame.RunModal();
modalResult.frequenciesHz

% Переходный отклик; строится DOF uy узла 3 только при plotting=true.
dynamic = StructFEProblem(fullfile('examples', 'cases', 'CaseBeamDyn.txt'));
transientResult = dynamic.RunTransient(1e-4, 1e-2, 3, 2);
```

Полная воспроизводимая проверка всех примеров, аналитических решений и ошибочных
входных файлов запускается командой:

```sh
octave --no-gui --quiet --eval "addpath(pwd); setup; run_octave_tests;"
```

## Результаты в элементах

Статический расчёт возвращает массив `elementResults` с результатами для каждого
элемента. Все величины вычисляются в локальной системе координат элемента с той же
матрицей преобразования и локальной матрицей жёсткости, которые используются при
сборке:

```octave
result = problem.RunStatic();
element = result.elementResults(1);

element.localDisplacements
element.localEndForces
element.axialStrain
element.axialStress
element.axialForce
```

Для стержней типа `112` положительные `axialStrain`, `axialStress` и `axialForce`
означают растяжение, отрицательные — сжатие. Для рамных элементов типа `113`
`localEndForces` имеет порядок `[N1; V1; M1; N2; V2; M2]`, соответствующий
локальным степеням свободы `[u1; v1; theta1; u2; v2; theta2]`. Это узловые силы,
действующие на элемент; при отсутствии распределённых нагрузок они согласуются с
реакциями и приложенными узловыми нагрузками.

Функция с прежним именем `StressCalc` переписана для нового интерфейса
`StressCalc(model, displacements)` и возвращает вектор осевых напряжений
ферменных элементов. Полный набор результатов следует брать из
`result.elementResults`.

## Элементы и сборка матриц

Элементы представлены обычными структурами данных, а не изменяемыми объектами.
Функция `createStructuralElement` создаёт единый интерфейс для стержней типа `112`
и рамных элементов типа `113`. Основные поля элемента:

- `type`, `nodeNumbers`, `nodeCoordinates`, `properties` — исходные данные;
- `dofs` — единственный вектор глобальных степеней свободы элемента;
- `length`, `transformation` — вычисленные и сохранённые геометрические данные;
- `localStiffness`, `stiffness`, `mass` — матрицы для восстановления результатов
  и глобальной сборки.

`assembleGlobalMatrices` собирает глобальные `K` и `M` из индексных триплетов и
возвращает разреженные матрицы. Поэтому память для больших сеток определяется
числом ненулевых коэффициентов, а не квадратом общего числа степеней свободы.
Численные решатели и структура возвращаемых результатов при этом не изменяются.
